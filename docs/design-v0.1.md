# 동방풍 브라우저 탄막 슈팅 — 설계 v0.1

작성일: 2026-09-16. 본 문서는 사용자가 제공한 확정 설계를 보존하고, 구현 계약을 추가한다.
게임 제목은 미정이다. 아래 임시 명칭·수치·콘텐츠는 사용자 확정 사항이 아니다.

## 1. 목표와 제약 [확정]

- PC 키보드 전용, GitHub Pages에서 실행하는 정적 브라우저 게임.
- 고전 동인 탄막 슈팅의 조작·템포·화면 문법. 현대적인 웹 대시보드 형태는 피한다.
- 논리 해상도 640×480, 좁은 세로 플레이필드와 별도 우측 HUD.
- 화면 비율을 고정하고 가능한 경우 정수 배율로 확대한다. 모바일 조작은 지원하지 않는다.
- PixiJS/WebGL은 표시를 담당하고, 게임 판정과 상태 갱신은 독립시킨다.
- 일반 구간은 빠른 웨이브 처리, 보스전은 저속 이동과 정밀 회피 중심.
- 일본풍 요괴·신사 계열 동양 판타지. 캐릭터·배경·음악·대사·사건·스펠명·개별 탄막은 모두 오리지널.
- 특정 원작의 스프라이트, 고유 패턴, 음악 또는 스토리를 복제하지 않는다.

## 2. 제품 범위 [확정 목표 / 단계 구분]

최종 제품은 메인 6스테이지 + Extra, 최소 2명의 플레이어, 캐릭터별 복수 Shot Type,
Story / Practice / Replay 모드, Easy / Normal / Hard / Lunatic을 갖춘다.
정확한 캐릭터 수, 최종 콘텐츠 및 해금 조건은 아직 미정이다.

구현은 다음 순서로 진행한다. 첫 단계가 완성되었다고 풀코스 완성으로 표현하지 않는다.

| 단계 | 산출물 | 완료 기준 |
| --- | --- | --- |
| M1: v0.1 플레이 가능 기반 | 1스테이지 + 중간보스 + 보스, 2명×2샷, 4난이도, 핵심 전투, Practice, 입력 리플레이, Pages 빌드 | 아래 수용 기준 통과 |
| M2: 메인 코스 | 2~6스테이지, 전체 보스와 오리지널 대사, 스토리 진행/엔딩 | 전체 코스와 난이도별 플레이 검증 |
| M3: Extra 및 마감 | Extra, 해금, 최종 그림/음악, 밸런스·브라우저 성능 검증 | 최종 콘텐츠 결정 후 별도 기준 확정 |

현재 구현 지시는 M1을 대상으로 한다. M2/M3를 위한 빈 시스템이나 가짜 콘텐츠는 만들지 않는다.

## 3. 조작과 화면 흐름

| 입력 | 게임 중 | 메뉴 |
| --- | --- | --- |
| 방향키 | 이동; 대각선 속도 정규화 | 항목/값 변경 |
| Z | 누르는 동안 연사 | 확인 |
| X | 누를 때 봄 1회 | 뒤로 |
| Shift | Focus: 저속, 피탄 중심 표시, 샷/옵션 변화 | — |
| Esc | 일시정지 | 뒤로/닫기 |
| Enter | — | 확인 보조키 |

키 자동 반복으로 봄이 연속 소모되지 않는다. 방향키/Space 등 게임 관련 키의 페이지 스크롤을 막는다.
창 포커스 상실/탭 숨김 시 입력을 비우고 정지한다. 복귀 시 밀린 시뮬레이션을 한 번에 돌리지 않는다.

흐름: 타이틀 → 모드 → 난이도 → 캐릭터/Shot Type → 게임 → 클리어/게임오버 → 재시작/타이틀/리플레이 저장.
Practice는 구현된 스테이지 또는 보스 연습을 제공하며, Story 기록과 구분한다.
일시정지에서는 재개/재시작/타이틀을 키보드로 선택한다.
미구현 2~6스테이지/Extra를 플레이 가능한 항목처럼 표시하지 않는다.

## 4. M1 임시 밸런스 [조정 가능, 미확정]

구현자가 플레이 테스트 후 바꾸면 실제 값을 구현 보고서에 기록한다. 값은 공용 설정 데이터에 모은다.

| 항목 | 초기 제안 |
| --- | --- |
| 플레이필드 | (24,16), 384×448; 좌표계는 필드 내부 기준 |
| 고속/저속 이동 | 3.8 / 1.65 px/tick; 캐릭터별 소폭 차이 |
| 피탄 반지름 / Graze 반지름 | 2.5 / 18 px; 탄환 반지름과 합산 |
| 초기 생명 / 봄 | 현재 생명 포함 3 / 3 |
| Deathbomb | 피탄 다음 입력부터 8틱 기회; 8번째 입력까지 허용 |
| 사망 후 무적 | 180틱 |
| 봄 | 180틱 무적, 발동 시 탄 소거, 효과 중 공격/탄 정리 |
| Power | 0~4.00, 단계 floor(Power); 소형 아이템 +0.05 |
| 자동 회수선 | 필드 y≤112; Power≥2.00 |
| Extend | 100,000 / 300,000 / 600,000점; 각 1회 |
| 탄 풀 | 적탄 8,192 / 플레이어샷 512; 초과 시 결정적으로 새 탄 무시 |

잔기는 HUD에서 현재 생명을 포함하는지 명확히 표시한다. 생명이 0이면 게임오버다.
죽으면 Power 일부 감소, 봄 3개로 재설정, 복귀 위치로 이동한다.
M1에서는 Continue 없이 재시작한다. 최종 Continue 규칙은 미정이다.

## 5. 전투 규칙

### 플레이어 / Shot

Z 홀드로 발사 간격마다 샷을 생성한다. Power 단계에 따라 샷 수·옵션 수·범위를 바꾼다.
Focus에 따라 옵션 배치와 집중도를 바꾼다. 표시만 다른 4가지 샷으로 끝내지 않는다.
M1 캐릭터/Shot의 이름·설정은 임시 오리지널이며 최종 설정으로 확정하지 않는다.

### 피탄 / Deathbomb / Bomb

플레이어 상태는 normal → pendingDeath → respawn 또는 bomb으로 전이한다.
충돌 순간 생명을 즉시 빼지 않고 8개 후속 입력 틱 동안 X를 받는다.
유효한 X와 봄 재고가 있으면 생명 손실 없이 봄을 발동한다.
봄이 없거나 창이 만료되면 사망 처리를 정확히 1회 수행한다.
일반 봄도 X의 상승 에지에서만 발동하며 진행 중 재발동하지 않는다.
무적 중에는 피탄하지 않는다. 두 캐릭터는 봄의 범위/효과 표현을 구분한다.

### Graze / Item / Score

각 적탄은 생존 기간 동안 플레이어에게 Graze를 최대 1회 준다.
실제 피탄과 Graze를 같은 탄에서 중복 지급하지 않는다.
적 처치 시 콘텐츠 데이터에 정의된 Power/Point를 드롭한다.
아이템은 낙하하고 근접 회수 또는 상단 자동 회수 조건에서 플레이어를 추적한다.
Point 가치는 회수 높이/자동 회수 여부에 따라 변화한다.
임시 점수: Graze당 100점, 적 처치 및 Point/Spell 보너스는 콘텐츠/설정에 명시한다.
Extend는 점수 문턱을 여러 개 한 번에 넘겨도 각각 1회 처리한다.

### 보스 / Spell

보스는 등장 → 통상 → Spell → 통상 → Spell → 퇴장/클리어 순서로 진행한다.
각 페이즈는 hp, 제한 틱, 패턴 ID/매개변수, Spell 이름/보너스를 정의한다.
HP 소진 또는 제한시간 종료 시 다음 페이즈로 진행하며 탄을 정리한다.
Spell 시작 시 보너스 자격을 초기화한다. 미스/봄/시간 초과면 해당 Spell 보너스는 없다.
노미스·노봄으로 시간 내 격파해야 보너스를 지급한다.
HP, 남은 시간, Spell 이름과 성공/실패를 표시한다.
중간보스는 같은 페이즈 구조를 재사용한다.

## 6. 난이도와 패턴

4난이도는 개수, 속도, 조준 빈도, 간격, 구조 변형을 각각 데이터로 갖는다.
탄속 하나만 곱하는 방식은 금지한다. Easy에서는 통로가 넓고, 상위 난이도에는 역회전/추가 조준 등을 넣는다.

M1은 함수 조합 방식을 사용한다. DSL 파서는 필요할 때 도입한다.
aimed, fan, ring, spiral, delayed burst 등 작은 발사 함수를 조합한다.
레이저는 최종 지원 후보이며 M1의 원형 충돌 탄환과 다른 판정을 미리 만들 필요는 없다.
패턴은 tick, phaseTick, difficulty, emitter, player 위치, seeded RNG, spawnBullet 함수를 입력받는다.
패턴에 DOM/PixiJS/실시간 타이머/Math.random 의존성을 두지 않는다.
새 Spell 추가는 콘텐츠/패턴 등록으로 가능해야 하며 BulletSystem을 수정하지 않는다.

## 7. 엔진 계약

TypeScript + Vite + PixiJS를 기본 구현 선택으로 사용한다. React는 필수가 아니다.
게임 결과를 결정하는 코드에서 브라우저 API를 참조하지 않아 Node에서도 실행할 수 있어야 한다.
시스템은 작은 함수/모듈로 분리하고, 모든 후보 시스템마다 클래스를 만들 필요는 없다.

### 고정 루프

- 60Hz 고정 timestep. requestAnimationFrame은 누산기와 렌더링만 담당한다.
- GameCore.step(inputMask) 1회가 1틱이다. 일시정지는 tick을 증가시키지 않는다.
- 한 화면 프레임의 catch-up 횟수를 제한한다. 숨김 후 재개는 누산기를 초기화한다.
- 입력은 각 시뮬레이션 틱 시작에 샘플링하고 같은 비트마스크를 기록한다.
- 갱신 순서를 고정한다: 입력/상태 → 웨이브/보스 → 플레이어/발사 → 이동 → 충돌 → 아이템/점수 → 페이즈/종료.
- 사망/보스 격파/아이템 회수 등 한 틱 내 중복 처리를 막는다.

### 시스템 책임

| 영역 | 책임 |
| --- | --- |
| GameCore | seed, tick, 상태, 고정 순서, 게임 설정 |
| Player | 이동, Focus, 샷, 봄, Deathbomb, 무적 |
| Enemy/Boss | 출현, 이동, 체력, 페이즈 전환 |
| Bullet | 풀, 위치 갱신, 수명, 화면 밖 회수 |
| Collision | 원형/연속 이동 판정, 적·플레이어 충돌 |
| Item/Score | 낙하·흡인·회수, Graze, 점수, Extend |
| Replay | 입력 저장, 검증, 재생, 호환 버전 |
| Renderer/UI | 상태 읽기, 스프라이트·HUD·메뉴·효과 |

빠른 샷이 적을 관통해 판정되지 않는 경우를 피하도록 선분-원 판정 또는 충분한 swept 판정을 사용한다.
렌더링 효과용 난수를 gameplay RNG와 섞지 않는다.

## 8. 콘텐츠 데이터

Stage: id, name, duration/waves, wave {atTick, enemyType, x, y, movement, pattern, drops}, midboss, boss.
Boss: id, name, phases {kind, hp, durationTicks, pattern, difficultyParams, spellName?, bonus?}.
Player: id, name, movement, hitRadius, shotTypes, bomb.

Stage ID와 보스 ID로 콘텐츠를 조회한다. 엔진에 stage===1 같은 전용 분기를 늘리지 않는다.
일반 웨이브는 60~90초 내외의 빠른 구간을 초기 목표로 하고 보스 페이즈가 이어진다.
최종 스테이지 콘셉트/배경/스펠 수는 별도 콘텐츠 제작 단계에서 확정한다.

## 9. 리플레이와 저장

리플레이 헤더에는 schemaVersion, gameVersion/contentVersion, seed, mode, stageId,
difficulty, playerId, shotType을 저장하고 body에는 틱별 입력 비트마스크 배열을 저장한다.
위치 스냅샷으로 재생하지 않는다. 같은 헤더와 입력을 GameCore에 공급한다.
입력 비트: Left 1, Right 2, Up 4, Down 8, Shot 16, Bomb 32, Focus 64.
일시정지/메뉴 입력은 gameplay 입력에 포함하지 않는다.

RNG는 명시적 uint32 상태를 갖는 seeded generator를 사용한다. seed 0 처리도 정의한다.
게임 로직에서 Date.now, performance.now, Math.random을 쓰지 않는다.
엔티티 순회/풀 슬롯 재사용 순서를 고정한다. 같은 버전·환경의 재현성을 테스트한다.
서로 다른 브라우저의 부동소수점/삼각함수 차이까지 완전히 보장했다고 주장하지 않는다.

JSON 다운로드/가져오기로 리플레이를 주고받는다. 크기, 배열 길이, 허용 정수 비트,
seed 범위, enum, 버전, 콘텐츠 ID를 검증하고 알 수 없는/과대한 파일을 거절한다.
초기 제한 제안은 5MB/216,000틱(1시간). 빈/깨진 파일에서도 게임을 깨뜨리지 않는다.
재생 중에는 조작을 섞지 않으며 일시정지/종료만 허용한다.
고득점/음량 등은 버전이 있는 localStorage에 저장하고 접근/파싱 실패 시 기본값으로 복구한다.
Practice/Replay는 Story 고득점 기록을 오염시키지 않는다.

## 10. 성능

적탄/샷은 사전 할당 풀(또는 typed array)을 사용한다. 초기화 이후 탄마다 새 객체를 만들지 않는다.
아이템/효과도 재사용한다. 렌더링은 재사용 스프라이트/텍스처로 배치한다.
플레이어 1명 대 N 적탄은 O(N) 검사로 충분하다. 샷 대 적은 적이 적으면 단순 검사로 시작한다.
이 선택에는 실제 한계와 spatial grid 전환 조건을 ponytail 주석으로 남긴다.
수천 탄 스트레스 검사를 제공하되 특정 기기 FPS를 측정 없이 보장하지 않는다.
풀 초과 정책과 최대 동시 개수를 디버깅 가능하게 한다.

## 11. 미술과 사운드

낮은 해상도, 명료한 탄 대비, 투박한 세리프/비트맵풍 글자, 전통 문양을 기본 방향으로 한다.
플레이필드 배경이 탄이나 피탄 중심을 가리지 않게 밝기를 제어한다.
Focus 피탄점은 실제 충돌 중심과 일치한다. 색상 외에도 탄 모양/밝기로 가독성을 확보한다.
에셋은 오리지널/라이선스 확인 가능 자료만 사용하고 출처를 기록한다.
가제나 자동 생성 이미지를 사용자 승인된 최종 타이틀/캐릭터로 취급하지 않는다.
M1에서는 오리지널 절차적 스프라이트와 간단한 합성 효과음을 허용한다. 최종 일러스트/음악은 미정이다.
오디오는 최초 사용자 입력 후 활성화하고 음소거를 지원한다. 음악이 없으면 완성 BGM이 있다고 표현하지 않는다.

## 12. 디렉터리

```text
src/
  core/       # 루프, GameCore, RNG, 설정
  systems/    # 전투·충돌·점수: 실제로 필요한 모듈만
  entities/   # 풀/상태 타입
  patterns/   # 패턴 조합
  stages/     # 웨이브/스테이지 정의
  bosses/     # 보스/Spell 정의
  players/    # 캐릭터/Shot 정의
  replay/     # 입력 기록·검증·재생
  ui/         # HUD/메뉴
  assets/     # 원본 리소스 또는 생성기
  scenes/     # 타이틀/선택/게임/결과
tests/        # Node 실행 가능 로직 검사
docs/         # 설계·작업 지시·실제 구현/검증 결과
```

빈 폴더/인터페이스를 억지로 만들지 않는다. 작은 영역은 한 파일로 합쳐도 책임 경계는 보존한다.

## 13. 빌드와 배포

npm install/ci → npm run dev, npm test, npm run build 명령을 제공한다.
Vite base를 상대 경로로 설정하여 GitHub Pages 저장소 하위 경로에서도 에셋이 로드되어야 한다.
Pages Actions workflow는 작성하되 원격 push/실제 공개 배포는 별도 지시 없이 하지 않는다.
클라이언트 비밀키, 서버, 데이터베이스는 필요하지 않다.

## 14. M1 수용 기준

1. 640×480/4:3, 우측 HUD, 키보드만으로 시작·선택·플레이·정지·재시작 가능.
2. 2명×2샷과 4난이도 선택이 실제 플레이 동작에 반영됨.
3. 이동/Focus/샷/봄/Deathbomb/Graze/Power/Point/자동회수/생명/Extend 구현.
4. 웨이브 → 중간보스 → 보스, 통상/Spell 교대, 제한시간/보너스/결과 처리.
5. 입력 replay export/import와 동일 seed+입력 최종 상태 일치 테스트 통과.
6. Deathbomb 마지막 허용 틱/그 다음 틱, Graze 중복, 풀 재사용, Extend/Spell 자격을 검사.
7. pause와 blur 이후 입력 고착·순간이동·따라잡기 폭주 없음.
8. 손상/비호환 replay 거절, 저장소 사용 불가 상황에서 실행 가능.
9. typecheck/build/test 통과. 브라우저 실제 시작/게임/정지/재시작 경로 확인.
10. README와 구현 보고서에 실행법, 구현 범위, 임시값, 실제 검증 결과, 남은 작업 기록.

## 15. 미정 항목 원장

게임 제목; 정확한 플레이어 수/설정; Shot 실제 성능; 이동속도/필드 크기/HUD 최종 배치;
점수 공식; Power 최대/성장; 초기 생명/봄; Deathbomb 프레임; Extend 조건;
