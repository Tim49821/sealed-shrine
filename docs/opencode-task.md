# OpenCode 구현 위임 — M1

사용자 지시: “설계문서 만들고 opencode 서브에이전트로 구현해”.
이 작업은 이미 구현 권한이 부여되어 있다. 설계 승인 질문으로 멈추지 말고 구현/검증까지 수행한다.

1. `docs/design-v0.1.md` 전체를 읽고 M1을 구현한다. 확정 목표와 임시값을 구분한다.
2. 반드시 OpenCode의 Task 도구로 `general` 구현 서브에이전트를 호출한다. Codex 내장 서브에이전트로 대체하지 않는다.
3. 파일 충돌 방지를 위해 구현 소유자는 한 서브에이전트로 시작한다. 필요하면 명확히 파일 범위를 나눠 추가 위임한다.
4. 주 OpenCode 세션은 통합/검증을 담당한다. 서브에이전트의 단순 완료 주장만으로 끝내지 않는다.
5. TypeScript/Vite/PixiJS/WebGL, 고정 틱 순수 로직, 시드 RNG, 재사용 풀, 콘텐츠 분리, 리플레이를 실제 연결한다.
6. 최소 의존성. 미정인 제목/캐릭터/수치는 임시로 명시. 원작 에셋 복사 금지. 절차적 오리지널 아트 허용.
7. 변경은 이 저장소 안에서만 한다. 외부 디렉터리 수정, git commit/push, 공개 배포, 비밀값 접근을 하지 않는다.
8. 사용자 기존 파일을 삭제/덮어쓰지 않는다. 두 설계/위임 문서는 의미를 바꾸지 않는다.
9. npm test/typecheck/build, 가능한 실제 브라우저 확인을 실행한다. 실패하면 수정하고 재검증한다.
10. `README.md`와 `docs/implementation-report.md`에 결과, 검증 명령/결과, 알려진 한계를 기록한다.
11. 완료 답변에는 구현 서브에이전트 세션/Task ID, 변경 파일, 확인한 테스트, 남은 범위를 짧게 보고한다.

M1 전체를 완료한다. 빈 메뉴/가짜 리플레이/한 난이도에 속도만 곱하는 구현으로 대체하지 않는다.
6스테이지+Extra는 장기 목표이며 이번 M1에 가짜로 채워 넣지 않는다.
